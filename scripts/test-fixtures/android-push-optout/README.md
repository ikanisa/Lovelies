# Android explicit push opt-out host fixture

Run `python3 scripts/test_android_push_optout.py` from any directory. The runner locates the repository from its own path and runs 69 focused checks. It compiles actual push, protocol, original-photo action binding, export/store recovery, account-page, upload-journal, session-authority and chunked-export sources with synthetic Android/Firebase/repository bindings. It also extracts and compiles the unchanged lease and ownership section of `OriginalMedia.kt`; those checks use a real temporary host filesystem and explicitly supply real host directory fsync. The Android `Os.open`/`fsync`/`close` default is not executed here: compile-only stubs throw if a fixture accidentally invokes it. The installed Android journey exercises that production default separately. Nothing in this directory is an Android release source.

For a retained receipt, pass `--evidence-dir /absolute/new/directory`. Set `KOTLINC`, `JAVA`, and `KOTLIN_COROUTINES_JAR`, or pass `--kotlinc`, `--java`, and `--coroutines`, if those tools are not on the host's normal paths. The runner hashes source, fixture and selected tool inputs before and after; it does not seal the entire JDK/compiler dependency closure. It writes only to the selected new evidence directory or its temporary directory.

The fixture does not contact Firebase, an app backend, an emulator, or a real notification manager. On macOS the **test process** is also launched with network access denied through `sandbox-exec`; on other systems the result explicitly states that only synthetic fakes provide the offline service boundary. The compiler itself is not OS-network-sandboxed. Tests cover local opt-out, app/channel permission, rotation and typed receipts; action ownership; lost export create/GET/staging/journal/ACK responses, corruption, document failure and expired/replaced sessions; file ownership, replacement and serialized cleanup; completed store-history retention; and pagination beyond 100, cursor corruption/cycles, session/account fences and explicit page size. Authority checks cover blocked writes, exact snapshot ownership, durable generations, cold-process retirement before restore, late credential publication, missing/corrupt markers, and retained uncertain journals. Large-export checks stream more than 20 MiB in 1 MiB chunks, including UTF-8 spanning a chunk boundary, stable create/ACK recovery, bounded manifest pagination, corruption and session/expiry rejection. A pass does not qualify Android SharedPreferences/Keystore/AtomicFile durability, real provider/store behavior, Compose/Activity lifecycle, document providers, MediaStore, FileProvider, or the separate notify/opt-out race. The complete Android application and repository-boundary JUnit tests still require the Android toolchain.
